# 改图文字指令识别

这份说明描述文字指令如何进入现有图片编辑流程。图片中的实际内容由编辑模型处理；识别规则不假装看到了图片，也不对图像做OCR。

## 常见表达

先引用照片，再说明修改要求。群聊可通过微信成员选择器@机器人，@可位于句首或句尾，支持微信特殊空格分隔。称呼从图片提示词两端移除，正文中的邮箱及明确要写入图片的@文字保留。

| 修改类别 | 示例 |
| --- | --- |
| 局部换色、换主体 | 把图里的小狗变成蓝色；将汽车换成自行车 |
| 换背景、场景转换 | 把背景换成沙滩；将人物移到月球上 |
| 添加配饰、物体 | 给小狗戴顶帽子；给背景加上彩虹 |
| 删除内容 | 去掉水印；把左边的路人擦掉 |
| 修脸、调光、细节 | 磨皮；提亮人物；虚化背景；修复老照片 |
| 构图与尺寸 | 裁掉右边空白；旋转90度；扩图到16比9 |
| 整体风格 | 将这张照片变成水彩风格 |
| 修改图中文字 | 把标题改成欢迎光临；把招牌上的字擦掉 |

支持“请、帮我、麻烦、可以帮我、能不能、能否”等请求前缀；人物、动物、物体名称不依赖固定白名单。规则匹配明确的动作结构，有界处理目标词，不把所有包含“图片”的聊天交给收费接口。

## 不自动执行的内容

- 普通图片评论、转述、假设、教程提问，例如“你觉得这样改怎么样”“如何把背景换掉”。
- 明确否定、暂停意图，例如“不要改图”“先别去掉背景”。
- 只有文字中的物体修改而没有图片引用：不能凭空选择另一张照片。
- 看图、提取图片文字等请求：不属于本次图片编辑识别扩展，不能冒充已经实现OCR。

已有显式“美化图片”等无引用命令仍会通过既有流程提示先引用图片。模棱两可的表达可能保持普通聊天；本规则没有承诺理解任意自然语言。

## 执行和验证

编辑请求继续经过原有参与决策、去重、单任务限制和冷却。先确认等待文字已发送，再加载当前引用照片；缺缓存按已验证流程下载，身份/MD5/解码全部通过才进入付费编辑。失败不自动付费重试。上线不回放历史已处理的消息。

测试入口：`tests/image-intent.test.ts`覆盖80种明确编辑表达、33种否定/讨论等负例及@/无引用边界；`tests/image-waiting.test.ts`覆盖生图和五种编辑表达的Mock等待、引用、回图、去重，以及不明等待回执不加载/不付费。完整105项测试、TypeScript检查和构建通过，日志为 `data/research/image-intent-batch-full-tests.log`。

分类回归与Mock不是新一轮微信真人改图验收；需要用户发送一条新的引用指令确认实际效果，不重放历史请求。
